# SECURITY_MODEL — نموذج الأمان

## 1. الأصول والتهديدات
| الأصل | التهديد | الضابط |
|---|---|---|
| ملفات Session (مفاتيح مصادقة) | تسريب/قراءة غير مصرّح بها | تخزين خارج git، تشفير Fernet at-rest، ملفات مؤقتة 0600 تُحذف فورًا، لا مسار/محتوى يُقدَّم عبر الواجهة أو التصدير |
| الأدلة | تلاعب/إنكار | SHA-256 عند الإضافة، سلسلة حيازة، تحقق دوري، manifest في حزمة ZIP |
| بيانات القضايا | وصول غير مصرّح | RBAC على كل نقطة نهاية، JWT موقّع بـ`APP_SECRET_KEY`، كوكي HttpOnly/SameSite=Lax (Secure في production) |
| الأسرار (DB/SMTP/Proxy) | تسريب في الكود/DB | بيئة فقط (`.env` خارج git)، `secret_ref` للـProxy، `config` backup يُخفي القيم الحساسة |
| سجل التدقيق | حذف/تعديل | جدول append-only بالمنطق (لا نقاط نهاية تعديل/حذف)، تصدير موقّع بالهاش |
| المنصة (Telegram) | إساءة استخدام الأداة | لا إرسال عبر Sessions، لا تدوير، احترام FloodWait، allow-list للعناوين الرسمية |

## 2. الهوية والصلاحيات (RBAC)
| الدور | يقرأ | يكتب | خاص |
|---|---|---|---|
| `admin` | كل شيء | كل شيء | users, backups, settings |
| `operator` | كل شيء | sessions, proxies, targets, cases, evidence, submissions, exports | تنفيذ التسليم (`submissions:execute`) |
| `reviewer` | كل شيء | cases | **اعتماد القضايا** (`cases:approve`)، audit, exports |
| `auditor` | كل شيء | — | audit, exports |
| `viewer` | كل شيء | — | — |
المصفوفة في `app/security/rbac.py::ROLE_PERMISSIONS`. كلمات المرور argon2 (passlib). أول مدير عبر `BOOTSTRAP_ADMIN_PASSWORD` أو `app users create`.

## 3. الفصل بين الأدوار في سير القضية
- المُشغّل يُنشئ ويُعدّ المسودة؛ **المراجع** يعتمد؛ التنفيذ يتطلب هوية مُعتمِد مسجّلة (`approved_by`) في `submissions` وفي Audit.
- المسودة تُقفل بعد الاعتماد؛ القضايا المغلقة غير قابلة للتعديل.

## 4. سجل التدقيق (§15, §28)
كل حدث يحمل: ماذا (`action`)، متى (`at`)، أي Session (`session_id`)، أي قضية (`case_id`)، من (`actor`, `ip_address`)، أي مزوّد (`provider`)، النتيجة (`result`)، سبب الفشل (`reason`). يُسجَّل أيضًا: تسجيل الدخول والفشل، إنشاء المستخدمين، التصدير، النسخ الاحتياطي والاستعادة، الوصول إلى ملفات الأدلة.

## 5. النسخ الاحتياطي الآمن (§30)
- منفصل لكل نوع: database (`pg_dump -Fc`)، sessions (tar.gz — تبقى مشفّرة إن كانت كذلك)، config (مُخفى الأسرار)، evidence.
- كل نسخة بهاش SHA-256؛ الاستعادة ترفض ملفًا لا يطابق هاشه؛ `restore` مسجّل في Audit.
- يوصى بتخزين النسخ خارج الخادم وبتشفير القرص.

## 6. حدود الاستخدام (ما لا تفعله المنصة)
1. لا تُرسل بلاغات عبر حسابات/Sessions ولا تُكرّرها من حسابات متعددة (§13، §27).
2. لا تدوير Proxy/Session لتجاوز قيود أو عقوبات (§4، §7).
3. لا محاولات متوازية لتجاوز FloodWait؛ التأخير المحدد من الخادم يُطبَّق حرفيًا.
4. الإرسال البريدي فقط لعناوين رسمية في allow-list وبموافقة صريحة وسجل تدقيق.
5. الإحصائيات للعرض فقط ولا تقود أي أتمتة.

## 7. توصيات النشر
- `APP_ENV=production` + HTTPS خلف reverse proxy، `APP_SECRET_KEY` ≥ 32 بايت عشوائيًا.
- مستخدم DB بصلاحيات محدودة؛ أذونات نظام الملفات: `sessions/`, `evidence_store/`, `backups/` بـ`700`.
- تدوير مفتاح التشفير: فكّ بالمفتاح القديم وأعد التشفير بالجديد (إجراء يدوي مسجّل).
